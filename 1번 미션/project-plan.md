## 2. 문제 정의와 프로젝트 기획

### 2-1. 한 문장 (초안, 팀 확정 전)

> **[건물·물류센터 시설관리 담당자]가 [공조기에 소음·풍량 저하·냉난방 불량 같은 이상이 생겼을 때] 겪는 [어디부터 점검해야 할지 모르는 혼선과, 서번 A/S 접수 시 필요한 정보를 빠짐없이 전달하기 어려운 불편]을 [증상 선택 → 점검 순서 안내 + A/S 접수용 요약 자동 생성]으로 줄이는 웹앱.**

상태: **가설** (팀 확정 필요)

### 2-2. 문제의 근거

| 근거 | 내용 | 종류 | 상태 |
|---|---|---|---|
| 서번 A/S 접수 안내가 현장명·모델·제조번호·증상·연동 장비 오류 표시·설치연도를 요구함 | 접수자가 알아야 할 정보가 많음 | 자료 (https://www.seobun.co.kr/service , 날짜 표기 없음) | 확인된 사실 (불편이 실제로 크다는 것은 아님) |
| 공기조화기 성능점검표에 외부 케이싱, 전동댐퍼, 동파방지, 풍량, 폐열회수장치, 소음·진동, 필터 상태 항목이 있음 | 공개된 점검 항목이 있어 순서 설계의 출발점이 됨 | 자료 (법제처 별지 제3호서식 https://www.law.go.kr/ , 2025-09-04) | 확인된 사실 |
| 현장 담당자가 증상에서 점검 순서를 바로 떠올리기 어렵다 | 문제의 핵심 가정 | 없음 (관찰·인터뷰 아직 없음) | **가설, 확인 필요** |
| 비전문 담당자가 증상을 부정확하게 전달해 A/S 왕복이 늘어난다 | 문제의 핵심 가정 | 없음 | **가설, 확인 필요** |

근거 보강 계획: ㈜서번 담당자 인터뷰 또는 서면 질의 (자주 오는 A/S 증상 Top 5, 접수 시 빠지는 정보), 실제 시설 담당자 1~2명 관찰·인터뷰.

### 2-3. 핵심 기능 (처음에는 2개만)

1. **증상 → 점검 순서 안내**: 증상을 고르면 확인 순서(쉬운 것부터, 안전한 것부터)를 단계별 체크리스트로 보여준다.
2. **A/S 접수용 요약 생성**: 입력한 정보와 체크 결과를 서번 접수 양식 항목(현장명, 모델·제조번호, 증상, 연동 장비 오류, 설치연도)에 맞춰 복사 가능한 문장으로 만든다.

제외(나중): 부품 재고 연동, 이미지 진단, 실시간 센서 연동, 수리 방법 안내.

안전 원칙(가설): 육안·외부 확인과 담당자가 할 수 있는 범위까지만 안내하고, 전기·냉매·분해가 필요한 단계는 "서번 A/S 접수"로 연결한다.

### 2-4. 화면 설명

**입력 화면**
- 설비 종류 (공기조화기 / 미리내 LSU / 공기순환기 / 모르겠음)
- 증상 선택 (예: 송풍기 소음·진동, 풍량 약함, 냉방 안 됨, 난방 안 됨, 누수·결로, 필터 경고, 열회수 장치 이상, 정지·경보)
- 발생 상황 (언제부터, 항상/가끔, 경보 표시 여부와 문구)
- 현장 정보 (현장명, 모델·제조번호 모르면 "확인 필요", 설치연도)
- 연동 장비가 있으면 제조사와 오류 표시 (서번 접수 안내 항목과 동일)

**결과 화면**
- 점검 순서 체크리스트 (1단계 안전 확인 → 2단계 외관·눈으로 확인 → 3단계 측정값 확인 → 4단계 서번 A/S 접수 기준)
- 단계마다 "정상이면 다음, 이상이면 여기로" 분기 표시
- 각 단계에 근거 표시 (공개 점검표 / 팀 가설 / 서번 확인 필요)
- 하단에 A/S 접수용 요약문과 복사 버튼, 서번 A/S 접수 링크
